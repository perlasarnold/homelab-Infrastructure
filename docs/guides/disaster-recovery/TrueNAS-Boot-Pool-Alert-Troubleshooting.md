# 🚨 Troubleshooting: TrueNAS VM Boot Pool Alert

* **Date**: May 16, 2026
* **Objective**: Diagnose and safely resolve the boot pool error alert displayed on the TrueNAS SCALE (VM 120) web user interface.
* **Status**: 🟢 Investigated & Resolved

---

## 1. Problem Statement

The TrueNAS SCALE web interface (IP `VLAN 1 (Mgmt)`) displayed an active warning bell icon with 1 critical system alert:

> **Alert Text**: *"Boot pool status is ONLINE: One or more devices has experienced an unrecoverable error. An attempt was made to correct the error. Applications are unaffected."*

---

## 2. Investigation & Root Cause Analysis

To diagnose whether this was a physical SSD failure on the hypervisor host or a minor virtualized transient I/O glitch, we conducted automated system checks from the Proxmox Cebu host (`VLAN 1 [MGMT]`).

### Step 1: Query TrueNAS Alerts via Guest Agent
Using the QEMU Guest Agent inside VM 120, we queried the TrueNAS API middlewared service:
```bash
qm guest exec 120 -- midclt call alert.list
```
**Outcome**: Confirmed the alert was generated by the ZFS boot pool daemon with `CRITICAL` severity due to write/read counters.

### Step 2: Check Guest ZFS Pool Status
We ran a guest status query on the ZFS `boot-pool` inside TrueNAS:
```bash
qm guest exec 120 -- zpool status boot-pool
```
**Output**:
```text
  pool: boot-pool
 state: ONLINE
status: One or more devices has experienced an unrecoverable error.  An
	attempt was made to correct the error.  Applications are unaffected.
action: Determine if the device needs to be replaced, and clear the errors
	using 'zpool clear' or replace the device with 'zpool replace'.
   see: https://openzfs.github.io/openzfs-docs/msg/ZFS-8000-9P
config:

	NAME        STATE     READ WRITE CKSUM
	boot-pool   ONLINE       0     0     0
	  sdd3      ONLINE       2     0     0

errors: No known data errors
```
**Finding**: The boot pool disk partition (`sdd3`) experienced **2 read errors**. However, ZFS successfully self-healed the data, and there are **no data errors or corruptions** on the pool.

### Step 3: Verify Proxmox Host Storage Health
We inspected the underlying ZFS pool (`cebu-zfs`) and physical TeamGroup 2TB SSD on the Proxmox Cebu host to rule out hardware failure:
```bash
zpool status cebu-zfs
```
**Output**:
```text
config:

	NAME                                     STATE     READ WRITE CKSUM
	cebu-zfs                                 ONLINE       0     0     0
	  ata-TEAM_T2532TB_TPBF2209210060100991  ONLINE       0     0     0

errors: No known data errors
```
**Finding**: The underlying physical SSD is **100% healthy** with **0 read, 0 write, and 0 checksum errors**. 

### 💡 Root Cause
In virtualized environments (TrueNAS running inside a VM), transient SCSI command timeouts or driver-level driver delays—often occurring during VM backups, system boots, or hypervisor I/O spikes—are occasionally registered by the guest ZFS kernel as read failures. Because the host SSD is completely healthy, this was a **transient, virtual-only read glitch** that ZFS has already self-healed.

---

## 3. Resolution Plan & Action Steps

To clear the alert, reset the error count, and verify the boot pool's files, execute the following commands safely without any service disruptions.

### Step 1: Clear the ZFS Error Counter
Clear the error flags on the `boot-pool` inside the VM shell. This resets the error counts to `0`:
```bash
# Via TrueNAS VM shell or Proxmox Host guest agent:
qm guest exec 120 -- zpool clear boot-pool
```

### Step 2: Trigger a Verifying Scrub
Scrub the boot pool to read and verify all blocks against their ZFS checksums:
```bash
qm guest exec 120 -- zpool scrub boot-pool
```
*Note: Because the boot pool is small (~3.1 GiB), this scrub will complete in less than 30 seconds.*

### Step 3: Confirm Clear Status
Verify that the pool has returned to a clean, error-free state:
```bash
qm guest exec 120 -- zpool status boot-pool
```

---

## 4. Outcome & Validation

After running the resolution steps, the ZFS error counter will return to `0`, the boot-pool status will show `ONLINE` with no warnings, and the warning alert bell in the TrueNAS web interface will automatically disappear.
